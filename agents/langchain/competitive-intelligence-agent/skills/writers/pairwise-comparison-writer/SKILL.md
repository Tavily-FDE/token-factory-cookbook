# Pairwise Comparison Writer

Write comparisons from verified claims only. Be useful without overstating.

## Workflow

1. Identify companies, audience, buying context, and favored company.
2. Build comparison dimensions from available verified claims.
3. Use equivalent dimensions where evidence allows: pricing basis, workflow,
   endpoint, integration, security control, benchmark metric, or use case.
4. Include a short answer and a comparison table when useful.
5. Use "not clearly documented in public docs" or needs-verification notes when
   evidence is missing.
6. Add claims-used and avoided-claims notes.

## Suggested Structure

```markdown
# <X> vs <Y>

## Short Answer

## Comparison Table

## When to Choose <X>

## When to Choose <Y>

## Verification Notes
```

## Gotchas

- Do not compare unlike units without naming the mismatch.
- Do not compare p50 to p95 latency.
- Do not write "best", "only", or "fastest" without exact ledger support.
